# DigiWard

A digital wardrobe you can search. Catalogue every garment by category, colour, material, season, formality and fit, then filter by occasion, weather and mood, spot gaps in the collection, and keep wear in even rotation.

The site is served at https://divitgangrade-lab.github.io/DigiWard/.

## Run it locally

Requires Node 20 or newer (developed on Node 26) and npm.

```bash
npm install
npm run dev
```

Open http://localhost:5173/DigiWard/ . The base path is `/DigiWard/` because that is how GitHub Pages serves the project.

```bash
npm test           # 48 domain tests
npm run build      # typecheck, then build to dist/
npm run preview    # serve the production build at http://localhost:4173/DigiWard/
```

`npm run hero` regenerates the hero fold study from `scripts/make-hero.mjs`. It writes `public/media/hero-fold.png`; no third-party image or CDN is involved.

## Publish it

`.github/workflows/deploy.yml` builds the site on every push to `main`, runs the tests, and deploys `dist/` to GitHub Pages.

One-time setup in the repository: **Settings -> Pages -> Build and deployment -> Source: GitHub Actions**. Until that is switched, Pages keeps serving the Jekyll rendering of `AGENTS.md` that was there before.

If you would rather keep branch-based publishing, run `npm run build` and serve the contents of `dist/` from a Pages branch, keeping `.nojekyll` alongside it.

## The item schema

One garment is one `WardrobeItem` in `src/domain/schema.ts`. Outfit combinations are tags on the item, and the wear log is an array of ISO dates on the same record, so a wardrobe file is one JSON list with nothing to join.

Required:

- `name`: what you call it out loud.
- `category`: tops, bottoms, outerwear, dresses, shoes, accessories.
- `color`: plain words ("oxblood", "indigo wash"), because that is what search reads.
- `material`: fibre or weave ("cotton oxford", "waxed cotton").
- `formality`: casual, smart-casual, business, formal.

Optional:

- `colorHex`: swatch on the card only. Does not affect filtering.
- `fitNotes`: shoulders, rise, sleeve and leg length, shrinkage. Worth filling in.
- `seasons`, `weather`, `occasions`, `moods`: arrays of the values listed in the schema.
- `tags`: lowercase outfit labels such as `winter-evening` or `desk-uniform`.
- `wearLog`: `YYYY-MM-DD` dates, one per day worn. The interface writes these for you.
- `care`, `notes`, `image`: free text and an optional photo path.
- `example`: true on the shipped samples.

### Fill these in first

The seven fields that outfit filtering and the gap report actually read:

1. `name`
2. `category`
3. `color`
4. `formality`
5. `occasions`
6. `weather`
7. `moods`

Then `fitNotes`, `material`, `seasons` and `tags` to sharpen suggestions, and the rest only if they earn their place.

## Filtering and rotation rules

Filtering (`src/domain/filter.ts`):

- Search is case and accent insensitive, and every whitespace-separated token must match somewhere on the item: name, colour, hex, material, fit notes, notes, care, category, formality, tags, occasions, moods, seasons, weather.
- Selections inside one facet are OR; different facets are AND.
- Missing optional arrays are treated as empty, never as a crash. An item with no `weather` will not match a weather filter.
- `unwornOnly` keeps pieces with no valid wear dates, including malformed logs.

Rotation (`src/domain/wear.ts`):

- Fewest wears inside the last 30 days comes first.
- Equal window counts are separated by total wears, then by the longest gap since the last wear.
- Exact ties are broken by name, then id, so the queue is stable between visits.
- Invalid or impossible dates (`2026-02-31`, free text) are ignored. Duplicate dates count once.

Gaps (`src/domain/gaps.ts`):

- Critical: a category with nothing in it, an occasion with nothing tagged, or a formality with no pieces.
- Notices: a category with one piece, an occasion with fewer than three, a formality with one, and any weather or season with no options. Weather notes are prompts to check against your own climate, not shopping instructions.

## Where your data lives

Everything runs in the browser. There are no accounts, no analytics, no cookies and no third-party requests after the page loads.

- The wardrobe is stored in `localStorage` under `digiward.wardrobe.v1`.
- Export writes `digiward-wardrobe.json` from your device.
- Import accepts an object with an `items` list (or a bare list). Valid items are kept, broken records are skipped, and the count of each is reported.
- If storage is blocked or full, the interface says so and keeps working for the session.

The sample entries are illustrative. Clear them before trusting the gap report.

## Tests

`npm test` covers the two areas the brief called out, plus the import path:

- `src/domain/filter.test.ts`: empty collections, blank queries, multi-field search, accents, missing optional fields, OR within a facet, AND across facets, unworn-only, tag counts.
- `src/domain/wear.test.ts`: empty collections, missing wear logs, invalid and duplicate dates, the 30-day window, equal wear counts, alphabetical and id tie-breaks, category filters, undo.
- `src/domain/gaps.test.ts`: an empty wardrobe, missing optional arrays, thin categories, custom minimums, a fully covered wardrobe.
- `src/domain/validate.test.ts`: required fields, unsupported enum values, tag normalisation, impossible dates, unsafe image paths, duplicate ids.
- `src/domain/template.test.ts` and `src/data/seed.test.ts`: the shipped template and sample catalogue always validate against the schema.

## Decisions and conflicts in the specification

The markdown files are authoritative. Where they left a choice open, or disagreed with the brief, this is what was decided:

1. **There was no application code to preserve.** Before this work the repository contained only `AGENTS.md`, `ANTI-AI.md`, `LEGALITIES.md`, `README.md`, `LICENSE` and `.gitignore`; GitHub Pages was rendering `AGENTS.md` through Jekyll. A React + Vite + TypeScript app was therefore created, because AGENTS.md section 5 explicitly requires integrating React Bits components (`DitherVeil`, with `ogl`), which are React components. No existing framework was replaced.
2. **DitherVeil is used once, in the hero, and only as decoration.** AGENTS.md section 5 requires it; ANTI-AI.md items 11 and 46 reject cursor-following glows and indiscriminate motion. The conflict is resolved by using the component for a single first-party image, with `wander` and `clickBurst` off, no rim colour, `prefers-reduced-motion` serving a static image, and the canvas marked decorative. The other React Bits components in AGENTS.md were not added, because stacking them would contradict ANTI-AI.md.
3. **Lenis smooth scrolling was not installed.** It hijacks native scrolling and works against the accessibility requirements in AGENTS.md and LEGALITIES.md. Anchor navigation uses native scrolling and respects reduced motion.
4. **Legal requirements are scoped to what the app does.** There are no accounts, payments, cookies, tracking, or user-uploaded public content, so cookie consent, PCI DSS, DMCA agent and CAN-SPAM requirements do not apply. Privacy, accessibility and disclaimer text sits in the footer disclosure; the site runs client-side only, so there is no server-side validation surface.
5. **Weather and climate defaults are flagged, not assumed.** The gap report treats weather and season coverage as "worth checking", and says so, because the user has not shared a climate.
6. **Fonts and the hero image are first-party.** Fonts are self-hosted with their OFL licences (`public/fonts/OFL-*.txt`), and the hero is generated by a script in this repository, so there are no third-party CDN requests and no attribution debt for stock photography.
